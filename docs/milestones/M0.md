# M0 – Scaffold

Status: **done**. One commit: `M0: scaffold`.

## What was built

`hmw-workbench` is now a C++20 Win32 + Direct3D 11 application with a Dear ImGui docking UI.

- **Repo**: `git init` (remote already configured, no push), `.gitignore`, four dependencies as git submodules in `deps/`:
  | submodule | repo | commit |
  |---|---|---|
  | `deps/imgui` | https://github.com/ocornut/imgui.git (branch `docking`) | `b1c1666c8` (v1.93.0-docking-96) |
  | `deps/ImGuizmo` | https://github.com/CedricGuillemet/ImGuizmo.git | `5b473bc30` |
  | `deps/json` | https://github.com/nlohmann/json.git | `322063822` |
  | `deps/DirectXTex` | https://github.com/microsoft/DirectXTex.git | `a8e5dbf42` |
- **Build**: `premake5.lua` (VS 2022, Release/Debug x64, `/W4` for our code, `/std:c++20`), `generate.bat`,
  `tools/build/build.bat` (submodules + premake + MSBuild, log in `build.log`), `tools/premake5.exe`
  (premake 5.0.0-beta1, copied from the local MWX tools, same as the MWX setup).
- **Window / UI**: Win32 window + D3D11 swap chain, Dear ImGui docking layout built on first start
  (`Assets` left, `Viewport` center, `Inspector` right, `Timeline` bottom). Layout is persisted in
  `imgui.ini` next to the exe; `View > Reset layout` rebuilds it.
- **Viewport**: 3D grid (1 unit spacing, brighter every 5), coloured axes (X red, Y green, Z blue),
  rendered into an offscreen D3D11 target and shown with `ImGui::Image` at panel resolution.
  - LMB drag: orbit; RMB/MMB drag: pan; wheel: zoom; `F`: frame camera. Camera readout is drawn in the
    viewport and shown in the Inspector (FOV slider + reset buttons).
- **Assets panel**: scans the configured roots and lists `weapons/*.json`, `xmodel/*.xmb`, `xanim/*.xab`
  grouped by kind, with a case-insensitive search box, hover tooltips with the full path and source root,
  a roots/asset summary tooltip, and a Rescan button (`File > Rescan assets`).
  Nothing is parsed yet (M1).
- **Inspector**: selected asset kind/name/path/root; camera info and FOV control.
  **Timeline**: placeholder ("arrives in M3").
- **Settings**: `workbench.json` next to the exe, created with defaults on first start; contains
  `assetRoots` (relative paths resolved against the exe folder, a trailing `*` expands to all
  subdirectories), `window.width/height`, `camera.{yaw,pitch,distance,fov}`, `lastWeapon`.
  The file is written on exit and via `File > Save settings now`.
- **Headless screenshot**: `-screenshot <file.png>` creates no window and no swap chain; it renders the
  grid into an offscreen target, saves it as PNG (DirectXTex/WIC) and exits. Optional
  `-width/-height/-yaw/-pitch/-dist/-fov` override the config for reviews.
- **Source layout** follows the plan: `src/app` (window, UI, settings), `src/assets` (scanning only, no
  D3D), `src/render` (D3D11 renderer, camera), `tools/`, `docs/`.

## Open issues

- **Disk space**: C: has ~13.8 GB free; the rules require keeping at least 20 GB. This was already
  below the limit before M0 (~15.1 GB); M0 added ~0.25 GB (submodules + build). Nothing was deleted
  outside the repo. The user needs to free space before M2 (dump folder) and M5 (`.xmb` saves).
- **`-info` and the other CLI switches** from the plan (`-weapon`, `-model`, `-anim`, `-attach`, `-camo`,
  `-view`, `-bones`, `-wire`) are not implemented yet – they are milestone features (M1+). M0 only adds
  `-screenshot` plus camera/size overrides.
- **`F` frames the world origin**, not an asset: there is no scene object or selection in the viewport
  yet. It will frame the selected model in M1.
- **Duplicate names**: the asset list shows a name once, from the first root that contains it (the plan's
  "first hit wins"). As a result `patch_common_mp` reports 0 models/anims and 54 weapons even though the
  folder has 107/1365/66 files – the names are shadowed by the HMW dump. If Claude wants per-root
  listings later, this needs a different index.
- **DirectXTex build**: the D3D12 helper (`DirectXTexD3D12.cpp`) and the GPU BC compressors
  (`BCDirectCompute.cpp`, `DirectXTexCompressGPU.cpp`) are excluded from the project: they need
  generated shader `.inc` files / D3D12. Only CPU paths and `SaveToWICFile` are used in M0; M1 readers
  will use the CPU decode/BC functions. No functionality of the plan depends on the excluded files.
- **Mouse interaction** was verified by code review and by rendering with camera overrides; no automated
  input injection was run. Manual check: launch, drag LMB/RMB, wheel, press `F`.
- **Workbench defaults are machine-specific** (absolute `C:\Games\cod-hwm\...` paths in
  `DefaultSettings`). If the game folder moves, edit `workbench.json` (it is generated once and then
  read), or the defaults in `src/app/settings.cpp`.
- Window size changes are not written back to `workbench.json` (camera is).

## Deviations from the plan

- Rendering goes to an offscreen colour target that is displayed with `ImGui::Image` instead of drawing
  the 3D scene behind the UI. This keeps the viewport correct at any dock size/aspect and reuses the
  exact same path as `-screenshot`.
- Extra CLI options (`-width`, `-height`, `-yaw`, `-pitch`, `-dist`, `-fov`) were added for review
  screenshots; they are additive.
- `tools/premake5.exe` is a committed build tool (1.4 MB), the same binary MWX uses; it is not a
  submodule because the plan lists only the four asset/UI dependencies.
- ImGuizmo is already a submodule and is compiled, but unused until M5.
- M0 also writes `imgui.ini` next to the exe (ignored by git) so reviewers get the same layout.

M1 was **not** started.
