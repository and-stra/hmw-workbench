# M3.1 - M4A1 reference match (FOV, camera handedness, ADS)

Status: **done**. Commit: `M3.1: M4A1 reference match`.

## Goal

Match the workbench's HMW M4A1 hip/ADS view to the in-game reference screenshots added by the user
(`references/m4/m4-hip.png`, `references/m4/m4-ads.png`, 1920x1016), report the sight pixel
positions, determine the matching `cg_fov` / viewmodel FOV, and fix the workbench defaults.

## Weapon and model used

The reference HUD says **M4A1**. HMW's M4A1 weapon asset is `h2_m4_mp`
(`szDisplayName: "M4A1"`), whose viewmodel is **`wpn_h2_m4a1_vm`**; its `handModel` is the
`viewmodel_base_viewhands` placeholder, so the workbench uses the faction default `viewhands_tf141`
(the same hands used for the M3 crossbow). The other M4 in the dumps is the H1 M4
`h1_m4_mp` (`szDisplayName: "WEAPON_M4_CARBINE"`, viewmodel `wpn_h1_asl_m4a1_vm_camo`), which is
not the reference weapon (and still misses its materials).

Everything below uses `h2_m4_mp` -> `wpn_h2_m4a1_vm` + `viewhands_tf141`, no attachments.

## FOV investigation

The HMW defaults (registered in the read-only `cod-mwx` source,
`src/client/component/patches.cpp:473-475`) are:

```
cg_fov      = 65     (horizontal FOV of a 4:3 view)
cg_fovScale = 1.0
cg_fovMin   = 1.0
```

IW widens `cg_fov` horizontally for widescreen (Hor+), so the vertical FOV is independent of the
aspect ratio:

```
fovY = 2 * atan(tan(cg_fov / 2) * 3/4)        = 51.077 deg for cg_fov 65
fovX = 2 * atan(tan(fovY / 2) * aspect)       = 84.16 deg at 1920x1016
```

The partial H1 decomp (`refs/hmw_decomp`) exposes `cg_fovScale` and `cg_fovMin` (and the HMW patch
registers `cg_fov`); there is **no separate `viewmodel_fov` dvar**. `cg_fovScale` is the viewmodel
FOV scalar, so at the defaults (1.0) the view weapon uses the same FOV as the world. The workbench
implements exactly that:

- `firstPersonFov` now means `cg_fov` (4:3 horizontal), default 65.
- `viewmodelFovScale` is `cg_fovScale`, default 1.0.
- The camera gets `fovY = VerticalFovFromCgFov(cg_fov) * cg_fovScale`.
- ADS uses the weapon's `adsZoomFov` (M4A1: 50 in the same 4:3-horizontal convention), giving
  `fovY = 38.553 deg`, `fovX = 66.92 deg` at 1920x1016.

The H1 decomp is stripped and does not contain the renderer function that reads the dvars; the
defaults and the dvar roles above come from the registration code and are confirmed by the
reference match (especially the front-sight X and the ADS aperture size/alignment).

## Camera handedness fix

M3 used a left-handed `XMMatrixLookAtLH` / `PerspectiveFovLH` pair. With CoD's Z-up, X-forward,
Y-left coordinates that put +Y on the **right** of the screen and mirrored the viewmodel (the gun
appeared on the wrong side, with rear/front sights reversed). M3.1 switches the camera to the
right-handed pair, so +Y (game left) is screen left. The M3 review images were regenerated after
this fix (using the M3-era `-fov 81.25` override to keep their framing; the M3.1 default is 51.077).

## ADS pose

`vm_h2_m4a1_ads_up` contains only the hands `tag_ads` bone (12 keys). It is a viewmodel offset, not
a full-body animation. M3.1 layers the end pose of that animation onto the current idle pose
(override `tag_ads` local rotation/translation, recompute the skeleton worlds) and switches the
camera to the weapon's ADS FOV. Replacing the primary animation with ADS_UP (the first attempt)
left the arms in their base pose and put the gun off-screen; the overlay reproduces the in-game ADS
sight picture. The inspector has an "Aim down sights" checkbox; the CLI has `-ads`.

## Pixel positions

Measured in the 1920x1016 images (the rear value is the aperture center, the front value is the
front sight ring/post center; reference values are the ones supplied by the user):

| image | rear sight | front sight |
|---|---|---|
| reference hip | (1380, 560) | (1095, 515) |
| workbench hip | (1360, 527) | (1094, 505) |
| reference ADS | (960, 510) | (960, 508) |
| workbench ADS | (955, 495) | (958, 500) |

The front sight X matches the reference within 1 px in hip and ~2 px in ADS; the rear X is within
~20 px (hip) and ~5 px (ADS). The remaining 10-33 px vertical difference is a small in-game
viewmodel offset/pitch that the workbench does not apply (it places the camera exactly at the hands
`tag_view`); it is not a FOV difference. At the M3-era `-fov 81.25` the gun was too small/too
centered, confirming that `cg_fov=65` is the correct hip FOV.

## Defaults and UI changes

- `firstPersonFov` default 65, `viewmodelFovScale` default 1.0.
- Inspector labels: `cg_fov (4:3 H)`, `cg_fovScale`, live vertical FOV, ADS FOV from `adsZoomFov`.
- New ADS checkbox and `-ads` CLI flag.
- Weapon JSON reader now exposes `adsZoomFov`.
- Camera is right-handed (Y left on screen).
- `-fov` is documented as a **vertical** FOV override (used for the M3 artifact regeneration with
  81.25); normal runs use the cg_fov conversion.

## Open issues

- The workbench does not apply the game's viewmodel offset/pitch; the hip rear sight is ~20 px left
  and ~33 px high, the ADS sight ~5/15 px high. The FOV and forward sight line match.
- ADS uses the `ADS_UP` end pose as a static overlay; there is no ADS idle/sway blend or transition
  timing yet.
- The reference images include the map/HUD and are much brighter than the empty workbench scene;
  the comparison is about geometry/FOV, not lighting.
- The crossbow (M3 artifacts) is very close and partially clipped at the correct 51 deg FOV; that
  port's viewmodel scale/offset differs from the H2 M4. The M3 crossbow images were kept at the
  M3-era 81.25 override for continuity.
- The H1 decomp is partially stripped; the viewmodel-FOV conclusion is based on the dvar
  registration (cg_fov/cg_fovScale) and the reference match, not on a recovered renderer function.
