# M6 - Camos

Status: **done**. Commit: `M6: camos`.

## Goal

Research how HMW applies camos to view models, document it with sources, then add a camo
dropdown, the `-camo` CLI and the `load_weapon`/`load_model` MCP parameters, and approximate
the material-defined look in the shader.

## 1. Research (written before the code)

`docs\camos.md` is the full write-up. Key facts and their sources:

- The loadout stores a camo name; scripts resolve it through `mp/camoTable.csv`
  (`refs\iw5-scripts\maps\mp\_utility.gsc:1394`; H1 compiled scripts
  `refs\h1_dump\h1_dump\scripts\42852.gsc:6,21`, `42891.gsc:2..4`). HMW keeps the same script
  surface (`table_getweaponcamo`, `getweaponcamoname`, `weaponcamoorder` in
  `refs\hmw_decomp\strings.tsv:5537,19279,23865`).
- The view-model material is swapped from script: `overrideviewmodelmaterial`,
  `overrideviewmodelmaterialreset`, `setviewmodelmaterialscriptparam`
  (`refs\hmw_decomp\strings.tsv:7253,7258,7259`).
- The plan's field name `camoViewModelMaterialOverride` **does not exist** in any HMW weapon
  json, HMW decompiled string table/binary or the H1 struct reference; the `_camo` model and
  material naming plus the script override is what the dumps contain. This is recorded in
  `docs\camos.md` section 1.
- The camo-ready material layout (typeHashes): dc1 design `659983135`, specular `887934131`,
  normal `1507003663`, second normal `1518176625`, occlusion `1610742065`, base colour `c`
  `2695565377`, camo mask `m` `3135443286`, camo spec `3426233914`.
  Example: `GAME\dump\workbench_hmw_ar1\materials\m\mtl_h2_m4a1_receiver_camo.json`;
  the crossbow already has the same slots
  (`GAME\zonetool\mod\materials\m\mtl_crossbow_base.json`: `camo_transparent_col`,
  `crossbow_col`, `crossbow_mask_02`).
- Camo designs: 355 weapon materials `camo_h1_*` in
  `refs\dumps\hmw_patch_common_mp\materials\` (550 including 195 `camo_h1_char_*` character
  camos), each with a 1024x1024 BC1 `wpn_h1_camo_*_col` dc1 texture and streamed pixel data in
  `GAME\dump\workbench_hmw_patch_common_mp\streamed_images`. Base MWR camos (`gold`,
  `woodland`, ...) are only in the H1 class script, not in these dumps.

## 2. Implementation

- `src\assets\material.h/.cpp`: texture `typeHash` parsed; constants for the camo slots.
- `src\assets\model_asset.h/.cpp`: `MaterialSlot::camoMaskImage` loads the material's `m`
  texture (typeHash `3135443286`) once per material.
- `src\assets\camo.h/.cpp` (new): `ListCamos` (355 sorted weapon camo materials, character
  camos excluded), `FindCamoMaterial`, `LoadCamoImage` (dc1 texture, accepts `camo_h1_x` or
  bare `x`), `CamoTextureName`.
- `src\render\renderer.*`: `GpuMaterial::camoMask`, `GpuModel::camo/camoStrength/camoScale`,
  `SetModelCamo`/`ClearModelCamo`, a white 1x1 fallback mask, `t3`/`t4` textures and
  `gCamoParams`. Shader: `albedo = lerp(albedo, camo, saturate(mask * strength))` inside an
  `if (strength > 0)` branch, so a no-camo frame is unchanged.
- `src\app\commands.*`: `SetCamo`, `ClearCamo`, `CamoNames`, `CamoName/CamoTexture`,
  `SetCamoStrength/Scale`; applied to the gun, the standalone model and mounted attachment view
  models (not the hands, not reticle models) and re-applied after load/attach/reload.
- `src\app\application.*`: Inspector *Camo* section: filter box, dropdown, Clear, strength and
  UV-scale sliders.
- `src\app\main.cpp`: `-camo <name>` plus `-camo-strength` / `-camo-scale`; works in
  `-screenshot` and window mode, on `-weapon` and `-model`.
- `src\app\mcp.cpp`: `load_weapon` and `load_model` accept `camo`; result includes
  `camo:{name,texture,strength}` or `camo:{name,error}`.
- `docs\mcp.md` updated.

## 6. Open issues / deviations

- The preview only replaces the diffuse colour; the real technique also swaps camo normal,
  specular and env response, so highlights on camo'd parts still use the weapon's base spec map.
- The camo design is sampled with the model UVs at scale 1 (the material data does not define a
  camo UV transform; `decalParams1` is a decal parameter). The UI slider can change the scale if
  a pattern looks too large.
- H2-native animated camo variants (`mtl_h2_m4a1_receiver_fire`, `..._doomsday`, `_misva_eflow`)
  are not in the `camo_h1_*` list and are not exposed; see `docs\camos.md` section 2.
- Camos to compare in game: `camo_h1_christmas_wrap` (bright green), `camo_h1_blue_jade` (teal
  zebra), `camo_h1_red_wash` (dark red) on the H2 M4 and the crossbow.
- The M4 handguard's own mask (`i_h2_m4a1_handguard_m`) is mostly black, so only the polymer
  panels are camo'd there; this is the game's material data, not a workbench bug.
