# M10 - Comfort features

Status: **done**. Commit: `M10: comfort features`.

## 1. Hot reload

- `Workbench` watches the files of the loaded asset: the weapon json, gun/world model `.xmb`,
  its LOD0 `.xsb`, the hands model, mounted attachment models, the current `.xab`, and (in
  character mode) the body/head/weapon models. The list is rebuilt after every load/anim change
  (`RefreshWatchedFiles`).
- `PollHotReload` (called from `Update` every window frame and from every MCP tool call) compares
  `std::filesystem::last_write_time`, debounces **400 ms**, then reloads the current asset while
  keeping the animation and time. The camera target/yaw/pitch/distance and first-person mode are
  restored after the reload; failures are reported in the status string.
- UI: Inspector → *Hot reload* (checkbox, reload count, watched file count, last status).
- MCP: `hot_reload {action:"poll"|"status", enabled}` returns `{enabled,pending,reloads,status,
  watched}`. Every `tools/call` polls first, so a client only needs to call any tool after the
  debounce.

Test (`tools\test\m10-hot-reload.ps1`, copy in `build\edit_test`, real file hashed):
load the copy (39 bones), add a tag and save it (40 bones), replace the copy file with the
pristine 39-bone model, poll twice with a 700 ms gap: **reloads 1**, bone count back to 39, real
model sha256 unchanged. `review\M10\hot-reload.txt` (5/5).

## 2. Compare mode

- `commands::RenderComparison` loads asset A, renders it, loads B, renders with the same camera,
  and composes one PNG:
  - **side**: A | white divider | B (output width `2*w+4`), each framed around its own bounds;
  - **ghost**: B alpha-blended over A at `-compare-alpha` (default 0.45), same orbit target so
    the silhouettes line up.
- CLI: `-compare <a> <b> -screenshot <file> [-compare-mode side|ghost] [-compare-alpha n]
  [-view ...] [-world] [-camo ...]`.
- MCP: `compare_screenshot` with the same parameters; returns the PNG content like `screenshot`.
- Worked example: crossbow vs H2 M4, `review\M10\compare_crossbow_m4_side.png` and
  `compare_crossbow_m4_ghost.png` (same yaw/pitch/dist), plus the standalone gun models
  `compare_m4_crossbow_models_side.png`.

## 3. Bone-name compare + rename map

- `scene::CompareAnimToModel` lists an anim's channels that have no model bone, after applying a
  rename table. `commands::CompareBones` loads the `.xab` and `.xmb` without a renderer.
- Rename table JSON: `{"old_anim_bone": "new_model_bone"}` (or `{"rename": {...}}`). It is
  applied while sampling: for a model bone, the first table entry whose target is that bone
  supplies the anim channel (`SampleBone` in `scene\animation.cpp`). No files are written.
- CLI: `-rename-map <json>` (used by all loads/screenshots), `-compare-bones <xanim> <xmodel>`
  (text report). MCP: `rename_map {path|clear}` and `compare_bones {anim,model,rename_map?}`.
  UI: Inspector → *Rig / anim map* (load/clear map, entries, "Compare current anim to rig").
- Test with a made-up mapping on the copy root: `review\M10\rename_map_test.json` =
  `{"j_mainroot":"j_gun"}`. `mp_jug_maniac_idle` against the 39-bone crossbow copy: 93 channels,
  **1 matched**, **92 missing**, 0 renamed without the map; with the map **2 matched, 1 renamed
  (`j_mainroot -> j_gun`), 91 missing**. The applied pose visibly moves the whole crossbow
  (`rename_map_applied.png` vs `rename_map_none.png`, different SHA256); see
  `review\M10\rename-map.txt` and `bone-compare_*`.

## 7. Open issues / deviations

- Compare is an offscreen composition (the viewport shows one asset at a time); the CLI/MCP
  modes are the full compare implementation. Side mode frames each object around its own bounds,
  so the two halves are comparable but not pixel-aligned; ghost mode uses the same orbit target.
- Hot reload watches asset files, not directories: a newly added file that is not part of the
  loaded asset does not reload until the asset is reloaded. Attachment/material/image changes are
  covered only if that file is in the watched list (model/surface/anim/weapon json); material
  json/image edits require a manual reload.
- The rename map resolves a model bone to the first table entry that targets it; duplicate target
  entries are not diagnosed.
- The M10 hot-reload test uses the MCP server's per-call poll; the window app uses the same
  `PollHotReload` from its frame loop.
- No writes outside the repo; the copy tests only touch `build\edit_test` (gitignored).
