# M5 - Tag editing and saving

Status: **code complete; one MCP copy-save check pending**. Commit: `M5: tag editing` (`23c650c`).

## Goal

Round-trip `.xmb` writer first, then tag editing (move/add/revert, UI + MCP), safe saving with
`.bak` + `.tags.json`, and the real crossbow fit (`tag_reflex`, `tag_acog`, `tag_silencer`).

## 1. `.xmb` writer and round-trip (before any edit)

`-roundtrip [report.txt]` reads every `.xmb` in all roots, writes it into
`build\roundtrip\<root>\<name>.xmb` (gitignored), byte-compares the files and re-reads each written
file.

```
hmw-workbench.exe -roundtrip review\M5\roundtrip.txt
```

Result: **523 files, 523 identical, 0 different, 0 errors**.

The writer (`src\assets\xmodel_document.cpp`) keeps the original stream as a token list
(strings/assets/arrays/offsets) and replays every unchanged token, so strings, shared arrays,
material references and unknown data survive exactly. `AssetStream` gained a read recorder; the
semantic model comes from the same `ParseXModel` path as the viewer. Editable arrays are
`boneNames` (+ one string per bone), `parentList`, `tagAngles`, `tagPositions`,
`partClassification`, `baseMat`, `boneInfo` and the header `numBones`; models whose bone arrays
are shared/offset are still round-tripped but editing is refused (the crossbow's are inline).

## 2. Editing (command layer, UI and MCP)

`Workbench` now loads the gun/standalone xmodel as an `XModelDocument` (on `LoadWeapon` /
`LoadModel`) and exposes:

- `MoveTagLocal` (pos/quat local to the parent), `MoveTagWorld` (gizmo), `AddTag` (parent,
  copy-from, or typed local transform), `RevertTag`, `RevertAllTags`, `HasTagChanges`,
  `EditableTags`, `TagPoseWorld`, `TagGhostWorld`, `SaveEditedModel`.
- Moving a tag updates its local/world transform, `baseMat` (world quat/trans), `tagAngles`
  (local quat encoded as int16 * 32767) and `tagPositions` (world position), then rebuilds the
  pose. Edits therefore show live during animation, hip/ADS, first person and orbit.
- `AddTag` appends the bone at the end (parents stay before children) and updates every per-bone
  array: bone name value + name string token, `parentList` offset, `tagAngles`, `tagPositions`,
  `partClassification`, `baseMat`, `boneInfo`, header `numBones`. New tags have no skinned
  vertices, so no surface/palette rebuild is needed.
- `RevertTag` restores an existing tag to the loaded/saved state or removes an added tag;
  `RevertAllTags` reloads the document from the file; the dirty marker is
  `HasTagChanges()` (UI: `* modified *`).

### Inspector / viewport

The Inspector has a **Tags (edit + save)** section: tag list (added tags marked), local position
and quaternion fields, Move/Rotate gizmo toggle, ghost toggle, "Revert tag", "Revert all",
"Save model" and an **Add tag** panel (name input + dropdown of the tags HMW attachments need from
the fit report, parent combo, copy-transform combo, local pos/rot). The viewport uses **ImGuizmo**
on the selected tag (translate/rotate, LOCAL) and draws the original position as an amber ghost
cross. Camera orbit/pan is suppressed while the gizmo is used. Live edits go through the same
command layer as the MCP.

### Save

`SaveEditedModel` (only when called): copies the original to `<name>.xmb.bak` if no `.bak` exists
(never overwrites), writes the model in place, writes `<model>.tags.json` next to it (all tags:
name, parent, local pos/rot, world pos, `added` flag), re-reads the saved file, replaces the
in-memory document and runs the same checks as `-validate` on it. The M5 crossbow save reported
`ok: 20 surfaces, 8 materials, 6 material json missing` (the known missing crossbow materials).

### MCP write tools

`move_tag`, `add_tag`, `revert_tags`, `save_model` (thin wrappers over the same commands) were
added to the MCP server; `get_tags` now reports the `added` flag on tags. `docs\mcp.md` documents
the parameters and an edit example. `tools\test\m5-edit.ps1` exercises move/add/revert without
saving: **16 checks passed, 0 failed** (`review\M5\mcp-edit.txt`).

## 3. Crossbow fit (the real use case)

`-fit-crossbow -weapon iw5_exocrossbow_mp` adds the tags, fits them and saves:

```
hmw-workbench.exe -fit-crossbow -weapon iw5_exocrossbow_mp -hands viewhands_tf141
```

- Added `tag_reflex` (parent `j_gun`, copy `tag_red_dot`), `tag_acog` (copy `tag_acog_2`) and
  `tag_silencer` (copy `tag_flash`) at the end of `vm_crossbow_base` (36 -> 39 bones).
- ADS fit uses the crossbow's optic overrides (`vm_crossbow_reddot_ads_up`,
  `vm_crossbow_acog_ads_up`) with the workbench's automatic reticle alignment **disabled**, so the
  tag position itself puts the reticle on the camera axis. The fit solver moves the tag in its
  parent space until the reticle aim is on the axis; both converged in one iteration to screen
  **(960, 508)** at 1920x1016 (ADS FOV 38.553 deg).
- Final local positions and offsets relative to the copied source tag (parent `j_gun`, identity
  rotation, so local == world):

| tag | source | final local (x y z) | offset from source |
|---|---|---|---|
| `tag_reflex` | `tag_red_dot` (3.242754, 0.000000, 5.735756) | (3.242754, 0.000064, 6.091953) | (0.000000, +0.000064, **+0.356197**) |
| `tag_acog` | `tag_acog_2` (3.377740, 0.000000, 6.027328) | (3.377740, -0.000000, 6.137207) | (0.000000, -0.000000, **+0.109879**) |
| `tag_silencer` | `tag_flash` (22.358553, 0.000000, 4.412825) | (22.358553, 0.000000, 4.412825) | (0, 0, 0) |

- Reflex ADS: the reticle is centred exactly, but the crossbow's built-in ring
  (`tag_sight_on` surfaces) is in front of the reflex lens and hides the dot. The review image
  `crossbow_reflex_ads_end.png` hides those five surfaces (`-hidesurface 0,1,3,18,19`) to show the
  centred dot; `crossbow_reflex_ads_end_ring.png` is the same view without hiding, for evidence.
  In game the ring still blocks the lens until the M4 `hideTags` port fix is made (that would be
  a weapon-json change, not allowed here).
- ACOG ADS: centred on the ACOG lens with no hiding needed (the ACOG reticle itself is dark in
  the workbench, the green crosshair marks the centre).
- Suppressor: `tag_silencer` exactly at `tag_flash`, the suppressor cylinder aligns with the
  barrel in the side and top orbit views.

## Open issues / deviations

- Reflex dot occlusion by the built-in `tag_sight_on` ring (see above). A `hideTags` entry on the
  weapon or the optic would fix it in game; not allowed as part of this tag-only port change.
- The ACOG reticle texture is very dark in the workbench; the crosshair (not a workbench dot)
  marks the centre. No alpha-blended reticle rendering yet.
- `tags.json` marks the three tags `added: true` as written. If the model is saved again, the
  reload makes them part of the baseline (`added: false`); the file still has name/parent/local
  transform, which is what a re-apply needs.
- The UI gizmo/ghost compile and the window loads the crossbow, but the interactive gizmo could
  not be driven headlessly. The numeric fields and the command layer are tested through the MCP.
- `roundtrip.txt` was generated after the crossbow save, so it includes the edited file
