# M3 - Animations

Status: **done** (with the additive/rig and data limits listed at the end). Commit: `M3: animations`.

## Scope

- `.xab` reader: frames, framerate, bone names, quantized/compressed rotations and translations,
  delta parts and notetracks.
- Apply animation to the combined hands + gun skeleton by bone name.
- GPU skinning with the blend weights read in M1 (rigid + 1-4 weights).
- Inspector anim list: all weapon `szXAnims` states, `animOverrides` (attachment + tree type) and
  all anims in the roots.
- Timeline: play/pause, loop, speed 0.1-2x, scrub, frame step and notetrack markers with names.
- Additive anims on top of IDLE (checkbox, approximation).
- Command layer shared by the UI and the CLI, with no ImGui types.
- First person: grid hidden by default (toggle); key light relative to the camera.
- CLI: `-anim`, `-time`, `-frac`, `-sheet N`, `-info <xanim>`.
- Review artifacts in `review/M3/`.

## Command layer

New `src/app/commands.*` (`wb::commands::Workbench`) owns the loaded assets, GPU models, camera,
pose, animation state and rendering. It has no ImGui dependency. The UI (`Application`) and the
CLI (`main.cpp`) both call it; neither calls the asset/scene loaders directly anymore.

Commands: `LoadWeapon`, `ReloadWeapon`, `LoadModel`, `ReloadModel`, `SetHands`, `PlayAnim`,
`StopAnim`, `SetAnimTime` / `SetAnimFraction` / `SetAnimFrame`, `SetAnimPlaying`, `SetAnimLooping`,
`SetAnimSpeed`, `SetAdditive`, `Update`, `SetViewMode`, `FrameCamera`, `SetOrbitView`,
`SetFirstPersonView`, `RenderScene`, plus plain accessors for the UI/MCP. Surface visibility,
wireframe, grid and exposure are plain state.

## `.xab` decoding

`src/assets/xanim.*` reads the x64-zt H1 tagged stream (`XAnimPartsRaw` 0xD8, then strings and the
arrays in dump order) and decodes:

- frame keys 0..`numframes` inclusive (`numframes=86` means 87 keys);
- none/2D/3D/static rotation groups (`DivideBySize`, s16 / 32768, normalized quats);
- normal (byte), precise (short) and static translations (min/size table + local values);
- 8-bit frame indices for < 256 frames, the inline/long-index path for >= 256 frames;
- notetracks as normalized fractions (seconds = fraction * duration, frame = fraction * numframes);
- `XAnimDeltaPart` translations / 2D quats / 3D quats, including the inline index and frame buffers.

The dump is tolerant of both null-tag and omitted-null-array dumper variants (the older zonetool
build used for the crossbow omits null optional arrays; the HMW dumps vary).

Verification: `-info vm_crossbow_reload` reports 86 frames (keys 0..86), 30 fps, 75 bones and 7
notetracks at frames 1/20/29/46/69/74/86. Delta decoding was exercised on
`h1_mp_melee_mantle_over_33` (13 translation keys) and on delta-flagged character anims with no
root-motion data.

## Combined skeleton + skinning

`src/scene/animation.*` builds the pose:

- hands bones first, then the gun model; the gun root (`j_gun` / `tag_weapon*`) is parented to the
  hands `tag_weapon` (fallback `tag_weapon_right` / `tag_weapon_left`).
- animation channels are matched **by bone name** (crossbow idle, reload and the HMW M4 anims all
  use different bone orders). Bones with no channel keep their parent-relative base pose.
- local values are parent-relative: `worldQuat = parentWorld * localQuat`,
  `worldPos = parentWorldPos + rotate(localPos, parentWorldQuat)`.
- delta root motion is applied to `tag_origin` when present.
- skinning palette per model bone: `inverse(bindWorld) * animatedWorld`; the gun bind pose is in
  gun space and its animated world is in hands space, so the gun is attached/animated without a
  separate world transform. Both models are rendered with identity world and their own palettes.
- the GPU shader uses a 256-bone constant buffer (`BLENDINDICES` / `BLENDWEIGHT`), normalizes the
  weights and transforms position/normal/tangent. Static models get an identity palette.

Evidence for the composition/pose is in [docs/viewmodel.md](../viewmodel.md): crossbow idle wrists
land at `(19.6,-1.5,52.2)` and `(5.2,-5.0,51.2)` with `j_gun` at `(8.2,-3.2,51.7)`; M4 idle gives
the analogous grip.

Blend weights (`src/assets/xsurface.*`): rigid vertices use `XRigidVertList.boneOffset / 64`;
weighted vertices come from the weight buffer (`boneId / 64`, `weight / 65536`) grouped by the
`blendVertCounts` classes (1-4 influences). The per-vertex bone ids were cross-checked against the
`BlendVertsUnknown` table on the `viewhands_tf141` surfaces.

## UI and CLI

- Inspector: weapon anim states (click to play), `animOverrides` with `attachment1` and
  `animTreeType`, current anim metadata and a filtered list of all anims in the roots.
- Timeline: play/pause, stop, first/prev/next/last frame, loop, additive-over-IDLE, 0.1-2x speed,
  scrub slider, notetrack markers with hover tooltips and a notetrack table.
- View: orbit / first-person radio, grid and wireframe toggles. First person hides the grid by
  default; `View > Grid` re-enables it.
- Key light: computed from the camera basis (front, slightly above/right of the weapon) so the
  receiver/handguard are lit in first person. The same light works in orbit.
- CLI: `-anim <name>`, `-time <seconds>` (or a 0..1 fraction with `-frac`), `-sheet N`
  (contact sheet; captions print anim/frame/time; cell size 480x270 unless `-width/-height` are
  given), `-info <xanim>` (frames, fps, bones with channel counts, notetracks, delta parts),
  `-grid` / `-nogrid`.

## Open issues / deviations

- **Additive animations are an approximation.** H1 stores additive keys as deltas relative to
  identity (`assetType == 6`; e.g. `vm_crossbow_empty_add`), but there is no reference pose or
  per-bone blend weight in the `.xab`. The checkbox multiplies the delta local rotation/translation
  onto the IDLE pose. It is implemented and listed, but not claimed to match the game's additive
  tree exactly.
- The **M4 reload sheet is visually extreme in first person** because the support arm comes very
  close to the camera (large grey sleeve) and the gun leaves the center of the frame. This is the
  authored 61-frame animation; the same pose looks normal in orbit. No animation data is missing.
- The **crossbow anims are IW5-authored** and are played on the MWR `viewhands_tf141` by bone
  name. The idle numerics put both hands on the weapon, but this relies on the rigs staying
  name/parent compatible; a true retarget step is not implemented.
- Animations with **more than 255 frames** use the long-index/long-frame path, which is
  implemented but not exercised by the M3 review assets (all <= 100 frames). Delta rotations
  (quat2/quat) are implemented; the delta anims found in the dumps only had translation data.
- GPU palettes are limited to **256 bones** (constant buffer). Viewmodels are far below that;
  character skeletons above 256 are not supported yet.
- The H1 M4 material gap from M2 is unchanged; the M4 review still uses the complete H2 M4
  (`h2_m4_mp` -> `wpn_h2_m4a1_vm`).
- The windowed timeline was not clicked through by an automated test; the window was verified to
  start with an animated weapon and stay alive. Headless playback, scrubbing (`-time`),
  frame stepping via the same commands and sheet rendering were exercised.
- The anim list order follows nlohmann/json's object ordering (alphabetical states), not the
  weapon file's visual grouping. All states are present.
