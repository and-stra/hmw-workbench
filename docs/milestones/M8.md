# M8 - World models

Status: **done**. Commit: `M8: world models`.

## Goal

Show the weapon's `worldModel` (and the attachments' `worldModels`, mounted by the same
root-bone/tag rule) in the orbit view; toggle view model/world model; `-world` CLI; MCP
`load_weapon world=true`; fit report for world models.

## 1. Implementation

- `src\scene\viewmodel.*`: `LoadViewmodel(..., bool world)`. With `world` it loads
  `weapon.worldModel` (falling back to `gunModel` with a warning), no hands, identity gun
  transform, world bounds from the model; `ViewmodelAsset::isWorldModel`.
- `src\app\commands.*`:
  - `LoadWeapon(..., bool world = false)` and `SetWorldModel(bool)`;
    `ReloadWeapon` preserves the mode; `LoadWeapon` forces orbit when `world`.
  - `Attach` picks `attachment.worldModels[0]` in world mode (fallback `viewModels`, error when
    both are empty); reticle view models are skipped (they are a first-person overlay).
  - `BuildFitReport(..., bool world)` + `AttachmentFitReport::world`: world model and world
    attachment models, same required-tag/nearest logic; `PrintFitReport` labels it `(world)`.
- `src\app\main.cpp`: `-world` (weapon load and fit report); the loaded model name is printed
  (`weapon: ... | model: npc_crossbow_base (world)`).
- `src\app\mcp.cpp`: `load_weapon {world:true}` (result has `world_model` and `loaded_model`);
  `attachment_fit_report {world:true}` (result has `world`, `gun_model` is the world model).
- UI: Inspector checkbox **World model (orbit)** next to the view-mode radios; toggles the
  loaded weapon between VM and world model and keeps the attachment set.

## 5. Open issues / deviations

- The world fit report shows the crossbow's **world** model has no `tag_reflex`/`tag_acog`:
  M5 added them only to `vm_crossbow_base`. If the game mounts world attachments from
  `npc_crossbow_base`, the same tags have to be added to that model (a normal tag-edit case;
  not done here because it would be another game-file write and no world fit was requested to
  be fixed, only reported).
- World models are static: no third-person anims are applied (M9 handles player models). The
  orbit view is the only world view; `-world` with `-view firstperson` stays in orbit.
- World attachments skip reticle view models (they are FP overlays); the attachment body still
  mounts/unmounts on the tag.
